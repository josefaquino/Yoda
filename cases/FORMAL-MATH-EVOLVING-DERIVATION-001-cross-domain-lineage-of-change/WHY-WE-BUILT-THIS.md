# Why We Built This

## The methodological question

This CASE exists to test whether **Lineage of Change** survives a domain change from biological artifacts to formal mathematical proof artifacts.

It is not a theorem-proving benchmark for Yoda.

It is not a Mathlib coverage benchmark.

It is not an OxiLean benchmark.

It is a derivation-integrity experiment.

---

## A failed measurement is not necessarily a failed hypothesis

A1.0 produced an important distinction:

```text
Lean
-> VALID

OxiLean
-> CANNOT CURRENTLY EVALUATE
```

It did **not** produce:

```text
Lean
-> VALID

OxiLean
-> INVALID
```

The first event is an instrument capability boundary.

The second would be a mathematical disagreement between authorities.

Only the first occurred.

---

## What A1.0 taught us

A1.0 did not invalidate Lineage of Change.

A1.0 revealed a capability boundary in an independent authority.

The original Complex-dependent workload caused the independent checker to traverse a dependency closure containing unsupported declarations.

The correct scientific response is not to hide the attempt and not to reinterpret `unsupported` as success.

The correct response is to preserve the measurement and revise the workload so that both authorities can exercise the role assigned to them.

## Negative results

### A1.0 — Capability Boundary Discovery

A1.0 is a permanent part of the research record.

```text
STATUS=NOT_EVALUATED
INTERPRETATION=CAPABILITY_BOUNDARY_DISCOVERED
```

Preserving this result matters because transparency about non-evaluable and negative measurements is part of the evidence discipline.

Hiding a non-passing attempt would weaken the audit trail.

Keeping it visible makes later claims easier to inspect and falsify.

---

## Research principle

```text
Do not rescue the experiment
by changing the engine.

Do not rescue the experiment
by weakening the authority.

Do not rescue the experiment
by relabeling unsupported as verified.

Preserve the evidence.
Identify the boundary.
Change only what is necessary
to make the hypothesis measurable.
```

> **Negative result = evidence. Capability boundary = discovery.**

The purpose of the CASE is not to manufacture a PASS.

The purpose is to learn whether the same derivation model survives a new domain under explicit, reproducible authorities.
